# Factual Decisions presentation

`compact-facts-2` preserves every canonical legal option, its original label mapping, exact afterstate, cells, path, rules, and next-five visibility. It adds literal surface-gap rectangles, nearly complete rows with empty-column coordinates, and individual hole coordinates with covering-block counts to the current and proposed boards. These are geometry facts, not reachability promises or heuristic values.

The last five confirmed actual board transitions supply hole/height/occupied-cell changes and cleared-line counts. The owner backend derives history during accepted placement or checked gravity settlement, including missed choices and automatic locks. Browser packets cannot supply history; resets clear it with the game epoch. A returned proposal that has not been acknowledged does not enter history.

The fixed teaching example compares two O placements on one literal board with a visible Z next. Its continuations are executable canonical engine outcomes. It is built once from fixed example data; no live candidate gets a continuation search, continuation count, rank, preferred label, combined evaluation score or recommended move. Earlier teaching examples retain their board consequences but omit preferred-answer labels in this presentation. The model chooses the native Choice value; the adapter only validates and maps it to the corresponding canonical ID.

`compact-facts-1` is retained as the first experimental neutral-instruction variant. The second version restores the previous hole-priority instructions, keeping the additional factual presentation. Previous formats are unchanged and remain available to owner-side controlled evaluations. This revision combines added geometry, confirmed history, a next-piece example, and revised instructions; paired results cannot attribute any difference to just one of those components. Teaching-board sequences must be excluded from claims about unfamiliar-sequence performance.

## Future general-model comparison

Terra/Sol integration is future work. A Responses adapter can use a strict structured output containing one legal move ID while retaining the same canonical evidence and execution checks. Model, endpoint, reasoning effort, usage including reasoning tokens, deadlines, credentials, project caps, and cost reporting need separate qualified contracts; the Decisions-only key is not proof of Responses authorization. No UI model selector or paid Terra/Sol call is enabled by this change.

Compare frozen-position decision quality and real-gravity performance separately. The same visible facts and assistance should be used for each model, with no local reranking, silent fallback, or automatic paid retry. A smaller visible answer does not eliminate billed internal reasoning tokens or establish adequate gameplay latency.
