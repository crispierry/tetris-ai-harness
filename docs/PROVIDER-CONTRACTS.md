# Offline provider adapter contract research

Original provider research checked 2026-10-24; Decisions guide/create contract refreshed by the admission coordinator on 2026-10-25 at 19:52 UTC (official sources below). Documentary preparation only; no provider request, credentials, account access or billing verified. Every adapter receives only a frozen public decision packet, never private RNG/seed or full internal simulator state. Live transport stays disabled without an explicit current run gate, external credential and hard request/token/cost limits. No silent retries, provider switching or fallback. Node-only credential boundary; browser never imports a key.

## Astra structured selection

`POST https://api.openai.com/v1/responses`, Bearer auth, explicit model `gpt-6-astra`. Responses structured output uses `text.format={type:'json_schema',name,strict:true,schema}`. Require only a selected legal candidate ID; do not request invented calibration/probability fields. Parse the response's message `output_text` item only after checking completion/refusal/incomplete status. Pin effort, standard speed and max output tokens in the run manifest. The model's current documented context/output limits do not establish this account's availability.

Sources: https://developers.openai.com/api/docs/guides/structured-outputs ; https://developers.openai.com/api/docs/guides/migrate-to-responses ; https://developers.openai.com/api/docs/models/gpt-6-astra . Pricing is a future run prerequisite, not permission or a current estimate of game cost.

## OpenAI Decisions

`POST https://api.openai.com/v1/decisions`, Bearer auth; current documented supported model is `gpt-6-luna`. Body: `{model,input,questions:[{type:'choice',name,instructions,choices:[{value,description?}]}]}`. Choice supports 2–255 unique typed string/boolean values. Use legal candidate IDs as string values. A one-candidate case needs an explicit deterministic controller decision, not an invalid one-option request. More than255 complete candidates fails explicitly as `unsupported_candidates` with zero transport attempts. Never truncate, split rankings or fabricate a second option. The API supports 1–400 questions; this contract sends exactly one named `placement` Choice question.

The native response requires a compatible reported `model` and exactly one answer named `placement`. Choice answer contains `choice`, `confidence`, `probabilities:[{value,probability}]`; refusals remain failures. Validate legal ID, correct question type/name, unique complete finite distribution and documented probability semantics. Confidence is not survival/win probability. Capture real model/usage/latency metadata without secrets. Input/candidate size must be bounded before dispatch.

Sources: https://developers.openai.com/api/docs/guides/decisions ; https://developers.openai.com/api/reference/resources/decisions/methods/create/ . Offline fixtures cannot prove a current account, price, model deployment or strategic quality.

## TypeSafe Jev

Original provider only. `POST https://api.typesafe.ai/v1/systemone`, Bearer auth. Documented body: `{model:'jev-latest',state,questions:{questionId:{type:'choice',instructions,criteria:{candidateId:description}}}}`. Answers are keyed by question ID, with `choice`, `confidence` and `probabilities:{candidateId:p}`; model and usage are top-level. Pin an actual discovered model version for a later measured run rather than assuming alias stability. `GET /v1/models` requires account authorization and was not called.

Docs describe32MiB request body and64nested levels; current Choice documentation specifies a maximum255 options. Actual model context capacity and exact applicable input price remain unverified; fail unsupported/oversize cases before any paid call. Do not claim output-free pricing or error-backoff strategy as free game execution. No automatic retries in the first bounded adapter.

Sources: https://docs.typesafe.ai/primitives/choice ; https://docs.typesafe.ai/api/system-one ; https://docs.typesafe.ai/api/list-models ; https://docs.typesafe.ai/api/errors . No unofficial proxy used.

## P8-008 offline implementation

`providers.mjs` is a Node-only module outside the static public directory. `createAstraAdapter()` defaults to unavailable with live calls disabled. Tests inject a function explicitly marked `mode: 'fixture'`; there is no fetch implementation, environment lookup, credential input, automatic retry or provider fallback. Passing `live: true` fails. This is an executable offline protocol adapter, not a qualified live integration. A future authorized live boundary must supply verified credentials, model access and externally enforced request/token/spend limits; the zero-dollar offline configuration does not authorize spending.

`runMetadata` exposes the exact requested model alias, reasoning effort, standard service tier (`default`), output/timeout limits, zero retries/spend, instruction/protocol/schema versions and fixture-only availability. `lastReceipt` separately records sanitized failure categories, latency, fixture-reported model/tier/token usage, selected ID, response hash and an optional fixture artifact reference. Fixture usage is labeled as such; actual API usage/cost and resolved live model version remain unknown. Raw response bodies and transport error text are not retained or exported. A response hash is an integrity value, not a claim that a raw artifact was archived; a missing artifact reference remains null. These Node-side records do not imply setup/status/cost UI delivery.

The strict Responses request lowers controller schema constants to one-value enums, preserves every offered candidate, and sends the complete self-contained public packet. The adapter returns only the three controller decision fields. Cancellation and timeouts abort the injected transport and suppress its late completion; the controller independently revalidates before execution. All failure classes represent adapter errors rather than a Tetris loss.

Dependency refinement pins the independently reviewed nonvisual controller/packet interfaces at `5c7a926484ac799b3867eba7e5c2e3b9c2799339`, tree `35f1fadd4ffefe836501aa00148f26d5e0fbecaa`, plus accepted P8-003/004/005/007. ## P8-009 offline Choice adapters

`choice-providers.mjs` exposes `choiceCapabilities(protocol)` and `createChoiceAdapter({protocol: 'decisions' | 'jev', ...})`. These are independently selectable Node fixtures. The manifest distinguishes documented capabilities from unknown authenticated availability/model identity. Decisions requests preserve the `gpt-6-luna` alias; Jev requests preserve `jev-latest` and retain compatible reported semantic versions as fixture data. Reasoning effort and service-tier knobs are explicitly unsupported by these request contracts rather than silently sent or presented as equivalent to Astra settings.

OpenAI's documented 2–255 option constraint is enforced. A single offered legal option returns directly with zero transport attempts, null confidence/distribution and an explicit no-provider-decision outcome. Both protocols document a maximum255 choices and preserve that bound; actual account/model availability and context capacity remain unknown. Larger packets fail without pruning, batching, fallback or changing shared search assistance. A later live Jev run must verify actual capabilities first. Model/capability discovery fixtures are not an authenticated provider lookup.

Both adapters receive identical complete rules/observation/candidate/afterstate evidence. Their response-format contracts remain separate (see P8-018 below). Decisions maps IDs to `choices` and reads its named array answer; Jev maps IDs to `criteria` and reads its named object answer. Returned distributions must contain exactly the complete unique offered set, finite probabilities in [0,1] summing to1 within1e-6, finite confidence in [0,1], and a selected maximum-probability option. Ties may select either maximum. Receipts retain provider-specific confidence meaning; neither confidence nor option probability is survival probability, game value or evidence of cross-provider calibration.

The fixture-only/default-off credential boundary, strict controller return shape, zero retries/spend, bounded deadline/cancellation, job ownership fencing and sanitized receipt conventions match Astra. No rendered provider selection, live operation, credentials, pricing qualification or P8-006 UI acceptance is delivered by this tranche.


## P8-018 normal-play packet and native Decisions boundary

Current decision schema is 3 and briefing is `local-rules-brief-3`; observation/candidate schema 2, geometry, engine rules, feature schema 1 and immediate afterstate mechanics are unchanged. `rulesBrief.instructions` contains reusable game semantics only. Object protocols (Astra and Jev) retain the controller packet's three-field `responseSchema` and separate `responseInstructions`. Decisions protocol `decisions-choice-2` serializes only `semanticPacket(packet)` into text `input`: schema version, observation, rules brief, objective and every current candidate. Its single native Choice question asks for a supplied placement ID, with no object-generation instruction or controller response schema. The adapter supplies authoritative `requestId` and `stateRevision` locally and returns exactly those plus `selectedCandidateId`; provider-supplied ownership claims cannot change that binding. Astra/Jev request and answer shapes stay intact. Frozen classic-v1 replay source and fixture bytes are untouched; unknown or mixed current contract versions fail closed.

Each current normal-play observation contains the locked board, active pose and exactly five ordered next pieces. Every reachable current placement includes its canonical orientation, cells, path, features and immediate consequences. There is no recursive/provider search, candidate pruning or later-piece planning in this protocol. Ordinary hypothetical afterstates spawn original `next[0]` and retain the original remaining four; successful Marathon afterstates retain all five, no active piece, no spawn/refill. The shared rules start at level 1, target 300 lines and cap level at 30; full final-clear scoring and overshoot lines are retained. Terminal states cannot create another decision packet. Depth-two local search remains a separately labeled local mode.

Both Choice fixtures enforce application bounds on the complete controller packet and actual serialized request body: each must fit configured `maxInputBytes` (default/maximum 1,048,576 compact-JSON UTF-8 bytes). Request measurement includes escaped text serialization, repeated IDs and Choice description overhead, before transport. Response bodies are bounded at 65,536 serialized bytes. The official gpt-6-luna model page (refreshed by the coordinator on 2026-10-25) documents a 1,050,000-token context and 922,000-token maximum input: https://developers.openai.com/api/docs/models/gpt-6-luna . These byte guards are not exact token/context estimates or proof that any request fits that token limit. Exact token qualification and framing margin remain required at the future P8-019/022 live boundary; this offline adapter cannot dispatch a live request and makes no token-fit claim. No `input_json`, cache implementation, reasoning effort, service tier or max-output knob is added. Future use of `input_json` would additionally require its documented container-depth/value/compact-byte bounds. Any reported cache-read/write token counters are subsets of input tokens, never extra input usage to add. Current receipts retain only fixture token usage and byte measurements; no actual API usage/cost is inferred.

One legal candidate is selected locally with zero transport attempts, null provider confidence/distribution and no serialized request body. Two through 255 candidates produce one complete Choice request. Invalid/oversize/unsupported packets, malformed or wrong named answers, unknown IDs, incomplete/duplicate/nonfinite distributions, wrong or missing Decisions model, refusal, authentication and rate-limit failures never execute a placement. The existing selected-maximum-distribution consistency rule and finite probability/confidence validation remain protocol checks, not estimates of game quality. Cancellation, deadline and Reset ownership fencing suppress late responses; retries and fallback remain zero. All observations here are injected offline fixtures. Live credentials, account access/model availability, transport and pricing remain unverified and belong to later work.
