# Bounded visible-piece lookahead

## Current player: selectable depth 1–6

The player menus expose one Lookahead model with a depth selector in Solo computer, Compare (independently per lane), and Human vs computer. The separate Local heuristic choice is removed. Depth includes the current piece: Depth 1 evaluates that placement, and Depth 6 evaluates the current piece plus the five visible upcoming pieces.

`public/beam-lookahead.mjs` implements `visible-beam-search-1`. It evaluates all offered roots, then retains the four highest-ranked branches after each complete placement layer. Only those retained branches expand at the next layer. This is approximate beam search, not exhaustive search; higher depth does not guarantee stronger play. Default limits remain 4000 nodes/calls, 500ms and 2MiB; comparisons can adjust the existing bounded search limits. A successful normal search reaches the selected depth. Known wins/losses can end a branch earlier. Exhaustion or cancellation returns no placement rather than silently substituting a shallower result.

Search uses canonical reachable routes and lock/clear/scoring consequences. Internal queue refills are stripped before the next layer. After the sixth known placement, the leaf is explicitly marked `horizon` with no active piece or preview; an arbitrary synthetic seventh spawn never contributes a terminal rank, board feature or evaluator input. Terminal known victories retain their unconsumed visible previews. Reports record requested/reached/selected depth, beam width, expanded states and pruned branches. Canonical saved-record verification checks the new policy and receipt counts while preserving historical depth1/2 records. Local/mock evaluators remain internal scoring components, with zero model calls and zero API spend.

## Historical exhaustive depth1/2 implementation

`public/lookahead.mjs` is browser-safe pure game/search code: no DOM, Node imports, credentials or transport. It exports `evaluateLookahead`, `createLookaheadProvider`, and local/mock leaf evaluators. Its retained historical policy is `visible-placement-search-2` with `local-leaf-value-2`. A provider still returns exactly `requestId`, `stateRevision`, `selectedCandidateId`; detailed search evidence is separate in `lastSearch` and `lastReceipt`.

Depth1 evaluates the supplied current-placement canonical afterstates. Depth2 expands one additional known piece through canonical reachable paths and simulation. There is no deeper search, hold, spin state, sprint, realtime policy or unseen-future expectation. The simulated internal state is reconstructed only from the public afterstate's board, active pose, counters and four remaining known queue entries. A fixed isolated synthetic randomizer fills engine bookkeeping internally. It cannot change the known next spawn or the evaluated board. Root evidence is rebuilt through the observation allowlist. A nonterminal child uses an explicit three-preview limit and verifies it equals the original remaining three; a winning child retains its four unconsumed known previews; it never uses the four-preview `candidateEvidence` helper for a child. No synthetic state, seed/RNG or generated queue entries are returned to an evaluator or report.

Every leaf evaluator receives full post-clear occupancy, active pose, known preview, features, placed cells, line/score deltas and terminal reason. Raw board/features and scalar value remain distinct. The default versioned heuristic is −5×holes −0.5×aggregate height −0.2×maximum height −0.2×bumpiness +8×cleared lines, with −1,000,000 for blocked-spawn loss and +1,000,000 for Marathon completion. Leaf values must be finite numbers within [−1,000,000,1,000,000]. Custom local/mock evaluators must declare a bounded policy/rubric and version. Live/model evaluators are unsupported. These values are not win probabilities, calibrated confidence or evidence of model quality.

Depth1 uses that leaf value directly. Nonterminal depth2 roots use8×root cleared lines + discount×best child leaf value; default discount0.9. Terminal roots stop immediately at their terminal leaf. A winning root retains all original five previews and is never expanded, at either selected depth. Equal values retain original root order, then canonical child order. There is no pruning or cache. Reports retain every root score and its best leaf with full occupancy; all child leaves are evaluated with full occupancy, while losing child leaves are discarded to bound report size. Cache is explicitly off; its documented future key would include rules, complete known state, feature/evaluator/objective and assistance versions.

Default limits:4000 placement nodes,4000 evaluator calls,500ms search time,2MiB report output, depth1. Maximums:4000 nodes/calls,5000ms time,4MiB output, depth2. A node is a supplied root placement or a simulated child placement; canonical reachability separately retains its800-pose/4000-transition limits. Search time is also bounded by the packet's decision deadline. Calls are local/mock leaf evaluations, not model requests; live model-call/spend caps remain zero. Configuration/input/caps are checked before work and after synchronous/evaluator returns; chunk yields permit cancellation. JavaScript cannot preempt arbitrary synchronous caller code, so an expired return is discarded. Evaluator functions are trusted executable inputs, not a network sandbox.

Node/call/time/output exhaustion, cancellation, invalid leaf values and evaluator errors fail the decision with no selected root or partial winner. Failed reports exclude partial root rankings. Evaluator scopes abort on completion/failure and clear timers/listeners; caller signals are not aborted. Reset→Step may immediately replace cancelled work; old cleanup/results cannot replace newer receipts. Progress reports distinguish offered/completed roots, enumerated children, visited nodes, evaluated leaves/calls, zero pruned branches, elapsed overhead and complete/failed status.

Failure envelopes obey the same output cap. Invalid request identities are not echoed; failed reports use a compact version/tier/evaluator reference rather than copying complete policy/formula text. Full policy stays in separately inspectable run metadata. Error codes and reasons use closed safe values, including when a callback rethrows or mutates an earlier search error. No raw evaluator text, partial ranking or oversized diagnostic detail is returned.

Run manifests retain the named depth/search/evaluator policy in player configuration. Depth1-versus-depth2 experiments are algorithm/assistance comparisons, not equal-assistance provider-quality tests. Any later Astra-versus-Decisions/Jev comparison must use the same external search and evaluator assistance for both competitors and retain a direct track. Saved-decision replay verifies chosen canonical transitions, not recomputation of search timing or live model responses.

Bounded offline paired runs report actual score/lines/survival, latency/overhead, failures, caps and sample counts; small capped examples do not establish an improvement or winner. P8-011 owns rendered settings/search summaries and full combined UI acceptance. Its labels must show depth/tier, limits, completed versus exhausted, explored/pruned counts, evaluator rubric and measured overhead. P8-006 enlarged-text acceptance remains separate; tool access/detection failure is not proof of a locked host.
