# Offline paired benchmark and saved-decision replay

`benchmark.mjs` exports `preflight`, `runPaired`, `replayRun`, `recomputeRun`, `aggregatePairs`, `stableJSON` and `digest`. It is Node-only and outside the public static directory. The default experiment is the accepted empty-board endless score/survival game, no hold, five visible previews and step-mode frozen game time. There is no sprint, victory condition or realtime comparison.

Call `runPaired({options, players, seeds, signal})` with two `{create: () => provider}` factories. Options require a bounded `runId` and a supplied 40-character `sourceRevision`; the caller must bind that revision to the checked candidate. The module records its own runner/code version, engine rules, schemas, feature and prompt versions. The revision string is not an automatic Git attestation. Each player/seed receives a fresh Controller and provider instance; shared provider objects and incompatible modes/configurations fail before decision invocation. Games share a private seed/ordinal piece sequence, not mutable state, RNG, board, clock, or request identity. Different placements and wall delays may produce different boards and survival; they do not justify move-by-move superiority claims.

Default bounds are100 placements/game,1500ms per decision,30000ms per game. Maximums are8 seeds,2 players,3000 placements/game,8000 planned aggregate placements,16032 events and32MiB exported artifacts, with decision/game deadlines at most60000ms. Invalid caps, unsupported hold/objectives/clock tiers and unknown settings fail preflight. Live mode is rejected; missing live budgets fail before invocation and supplying a budget does not enable live execution. Offline budget/retry counts are zero. Local/mock factories are trusted executable inputs, not a network sandbox; the runner has no network transport or credential lookup.

Seeds are supplied privately and are absent from manifests, provider metadata, events and exported artifacts. Exports contain only a seed-set/reference/index, observed piece consumption and public observations. Supply the original private seed separately to replay. No unseen future sequence is supplied to players. Exported completed-game observations are runner/replay evidence, never a replacement decision packet for another competitor.

Every attempted decision records its session/request identity, public packet/candidate digests, before/after observations and `observationHash` values, selected ID, commit count, consumed piece, safe failure class, latency and optional current-request fixture usage. These hashes describe public observations and packets, **not full private engine/RNG state**. Model/configuration/prompt/assistance identity stays in the manifest. Fixture token counts are labeled; actual API usage/cost remains unknown. Raw provider error text and response bodies are not exported.

Primary provider failures and opt-in `fallback: 'local-heuristic-explicit'` assistance are separate events. Assisted placements are never credited as unassisted provider success. No fallback follows cancellation, timeout, exhausted game deadline or budget stop. Typed stop errors are captured before the controller's message-only boundary; decision timeouts, budget stops and cancellation retain distinct outcomes. Cancellation/deadline aborts the controller and rejects late results; synchronous local code cannot be preempted by JavaScript timers, so its post-deadline return is discarded before execution under both per-decision and game bounds. Natural top-out on the cap-reaching placement is `game-loss`; reaching a cap first is censored, never victory. Partial/unpaired cancellation is explicit and excluded from complete-pair sample counts.

`replayRun(manifest, record, privateSeed)` constructs a fresh canonical Controller with a saved-decision provider. It makes no fresh provider calls, verifies regenerated packet/candidate digests and request bindings, executes saved IDs, checks every observation/placement transition and terminal precedence, and rejects mismatched versions, hashes, counters or choices. It verifies the recorded outcomes, not the original wall-clock timing, provider confidence or billing. Saved latency and usage can be recomputed as recorded metrics, not independently reproduced by replay.

`recomputeRun(record, manifest)` validates observation chains/counters, manifest-bound primary/fallback transitions and provider identities, and terminal-specific cap/failure/stop evidence. It reduces exported events into score, lines, level, committed pieces, consumed sequence, typed failures, assisted placements, latency quantiles and explicit censoring. `aggregatePairs(runs, manifest)` verifies same-ordinal consumption and produces sample counts, paired differences/ranges, outcomes, assistance and failures. External stop/timer facts remain recorded control evidence, not independently reproduced wall-clock events or cryptographic attestations. These are descriptive samples with no significance or inferred winner. Full observed model quality, live paired experiments and provider pricing require later current authorization and evidence.
