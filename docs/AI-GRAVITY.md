# AI gravity

Solo computer, Compare and Human vs computer start with **Gravity on**. The switch lives in the existing control rail, locks with the player settings, and unlocks after Reset. Compare applies it to both boards. Human gravity is unchanged. Board position and size do not depend on the setting.

With gravity on, engine time advances while a decision is queued or being calculated. Gravity uses the same level intervals as human play: 800 ms per row at level 1, multiplied by 0.85 each level, with a 100 ms minimum. A response is revalidated against the current falling pose. Immediate horizontal moves and rotations follow a newly derived legal route; downward route steps and final descent wait for engine gravity. No hard drop is substituted for the final fall. If the original target is unreachable, the choice is discarded and the piece continues its real fall. Autoplay can keep falling into the next piece before an old response arrives. Step caps the operation at one piece. A provider error/deadline pauses the run; no automatic retry or replacement decision is made.

Gravity off retains the existing paused decision controller and 350 ms placement animation. Run pace applies to this simulation mode and saved-frame replay. Gravity mode adds no artificial per-piece pace wait. Synchronous preparation, browser scheduling, and server acknowledgement can add small gaps between turns; this is a browser game, not a timing-authenticated benchmark.

Pause/Stop/Reset, window blur, page hiding and disposal fence the clock and late work. Partial falls are retained on Pause; Reset creates a fresh session. Reduced motion affects optional presentation only, never gravity. Saved-frame replay makes no decisions and retains the original exported bytes; it does not reconstruct live wall-clock timing.

## Checked state and accounting

`ai-gravity.mjs` is a pure one-turn reducer shared by the controller, Node verifier and browser Decisions service. Its bounded proof records exact elapsed waits, the original chosen ID, a placement bound, and the subsequently observed preview pieces. The route is rederived locally, never supplied by the model. Multiple natural locks and partial falls remain distinct from a successfully applied choice. Public records add `timing: real-gravity-v1` to the player policy and a `gravity` event. Intermediate live poses are provisional until the turn event is retained. A recording-capacity failure stops play and exports the earlier verifiable prefix, rather than claiming unrecorded movement. Existing paused records and fixture workflows stay supported.

A browser Decisions response is a plan, so a gravity receipt records zero committed placements. The authenticated `settleGravity` control replays the proof, compares the exact public result, updates real placement counts/continuity, and acknowledges delivery. Forged states, replayed settlement, unknown candidates and out-of-bound traces are rejected. Gravity accounting has a separate version because natural locks can outnumber completed model requests. Choices alone share one upstream lane; both boards' clocks keep moving. Failed or ambiguous upstream/acknowledgement still requires reconciliation. No retries, allowance refills, credential changes or budget changes are introduced. The approved $1 project limit and its billing-delay warning remain unchanged.

The original strict/pilot qualification paths retain their paused contract; real-time gravity uses the owner-paired browser Decisions path. Offline tests use local players and dummy HTTP upstreams, with no real API calls.
