## User experience and labels

The page title is “Compare computer players.” The introduction says that both players run locally, describes mock players as test fixtures, and states that Astra, Decisions, and Jev are unavailable because live adapters are disabled. Show those three as disabled options with “Unavailable — live connection not configured”; do not present them as playable, estimate their availability, or imply live/model results.

Show two equally prominent, independently labeled play cards side by side on desktop and stacked on narrow screens. The default comparison is `Local heuristic` versus `Lookahead depth 1`; allow `Lookahead depth 2`, `Delayed mock`, and `Error mock` as local/mock choices. Each lane has its own board, status, score, lines, level, pieces, next-five preview, selected candidate summary, and last error. Mark an assistance tier on each lane. A lookahead comparison is explicitly an algorithm/assistance comparison, not model quality or equal-assistance provider evidence.

The initial state shows two empty boards, the deterministic paired-run setup, ready statuses, one short controls explanation, and enabled player/settings choices. Use independent lane statuses: Ready, Running, Choosing, Paused, Stopped, Game over, Error, Completed, and Saved replay. A top-out or error in one lane does not stop the other. Preserve the failed lane’s last board and explain recovery; no silent fallback. Settings freeze when the run starts and remain frozen until Reset.

Provide shared `Start`, `Pause`, `Step one piece`, `Stop`, `Reset`, and `Replay` actions. Start advances both eligible lanes at the configured bounded pace. Pause cancels pending decisions in both lanes; late results cannot mutate either board. Step processes one decision for each eligible lane and then leaves the run paused; a failed lane remains in Error while the other can complete its step. Stop retains boards and run evidence. Reset restores both empty boards and the same private seed set/settings for reproducibility. Replay is available only for a saved run, labels itself `Saved replay`, and advances stored observation frames without requesting new decisions. It is visual playback, not a fresh decision run or Node canonical replay verification.

The collapsed Advanced panel exposes sample count (1–8), per-game piece cap, bounded play pace, lookahead depth, node/time limits, and evaluator/policy version. Reject invalid or over-cap settings before Start and explain the rejected value. Keep seeds private in local runner memory; do not expose them to decisions or export them. Do not add hold, spin, ghost-piece, sprint, or other unsupported mechanics.

## Run data and truthful reporting

Run matched deterministic seed/ordinal sequences through independent lane states, RNGs, clocks, and controllers. Each lane may choose different placements, scores, line clears, survival, and latency. Results show actual score, lines, pieces, terminal/censored status, failures, assistance, and measured local decision/search overhead. For multiple samples, display expected/observed/missing paired counts, per-pair differences/range, and censoring. Use descriptive wording only; never declare a winner or claim improvement from the interface.

Secondary expandable details show the current candidate’s placed cells/path, factual features, rule and score consequences, visible horizon, plus depth/tier, node/call/time/output limits, offered/completed roots, explored children, evaluated leaves, pruned count, and complete/exhausted status. Keep the two queue previews and board summary visible; keep worked rules/examples below the primary play area. Distinguish raw board features from scalar heuristic leaf value. Search exhaustion is a visible bounded error with no partial winner or committed placement.

`Export run` saves the run record and stored observations for visual replay. Exclude private seed values, credentials, raw provider responses, and hidden future pieces. Mark fixture usage and actual cost as unknown/not measured where applicable. The visual browser replay does not replace P8-010’s Node replay verification. No arbitrary import of untrusted records is required in this tranche.
