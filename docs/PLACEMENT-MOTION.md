# Placement presentation and cooperative Depth 2 search

AI motion is a view of an already committed placement. Controller execution, canonical journaling and any provider commit confirmation finish before the optional facade `onPlacement` hook starts. The hook receives the actual pre-decision Choosing observation, canonical after-observation, bound request, actual path and placed cells. First Step therefore has a real falling-piece pose even though the earlier ready screen has no active piece.

During decision/confirmation emissions the UI holds that prior visible board. During presentation it labels the lane “Placing…” and shows legal poses along the actual engine route, including rotation kicks and tucks. Hard drop is expanded into legal downward poses. The normal presenter lasts about 350 ms; score, line clear, next preview and the canonical final board are revealed together. This delay is excluded from decision latency and observed decision-attempt accounting.

Each lane awaits only its own presenter before its next choice and existing pace delay. Human input and gravity in versus remain independent. Start/Step are busy during presentation; Pause/Stop immediately settle to the committed final board and add only their ordinary lifecycle controls. Reset, sample changes, replay entry, page exit and disposal abort owned presentation work and fence old callbacks. Canonical errors and provider holds are shown rather than animated over. Actual `prefers-reduced-motion: reduce`, or an environment without motion APIs, reveals the final state immediately.

Replay uses only a saved path and adjacent states for the same lane when the piece count advances exactly once. Missing starting pose/path or invalid visual evidence falls back directly to the saved final frame. Replay never asks a chooser or executes an imported route as a game action. Intermediate poses are transient UI data, never added to canonical events, receipts or exports. Saved export bytes remain stable while replaying.

Depth 2 still performs the complete declared root/child search with the original root order, tie order, 500 ms default, 1500 ms decision deadline and 4000-node/evaluator caps. Its cooperative scheduling now uses an owned MessageChannel with approximately 8 ms time slices instead of repeated zero-delay timers, avoiding accumulated browser timer clamping. Every success, cancellation, malformed input and exhaustion path closes both ports and removes the abort listener. Arbitrary asynchronous leaf evaluators retain their timeout and cancellation guards. Exhaustion still selects no partial winner and places no piece; UI copy points comparison users to Advanced settings and versus users to another algorithm.

Source tests cover canonical route legality, clear/terminal/soft-lock/wall-kick/tuck paths, deterministic motion frames and reduced motion, post-confirmation gates, independent lanes/human play, lifecycle fences, replay identity and complete-search equivalence under a browser-like timer clamp. Actual responsive/intermediate-frame browser acceptance remains a separate operator check. This change does not renew or alter any provider session or budget.
